# 需求分析

## 1.配方管理

    只和SysRecipeInformation挂钩，该界面只在Loading时出现一次
    1.新增配方：弹出窗口可以输入配方信息，新增文件夹
    2.删除配方：删除数据和文件夹
    3.编辑配方：弹出窗口可以编辑配方信息，：保存判断是否重命名，如果是，执行重命名方法；如果不是则更新数据
    4.应用配方：新增配方cache.db

## 2.配方编辑

    在导航栏Recipe中，包含切换配方、配方编辑

### 2.1 切换配方（生产过程中）

    界面加载所有配方，选择后应用，关闭窗口

### 2.2 编辑配方

    1.仅限编辑当前应用的配方，配方编辑按钮点击后直接弹出配方编辑窗口
    P8、P5、明暗场Alignment Tool、WaferMap、MaskTemplate
    
    
    2.保存配方

# 2. Guard Service

## 2.1 配方一致性验证

### 2.1.1 配方文件合法性

    1. 检查文件夹是否已存在
    2. 检查文件夹是否包含cache.db

## 2.1.2 验证配方默认路径下文件合法性

    1.配方文件合法性

### 2.1.2 配方数据源和admin.db的完整性和一致性

    1. admin.db中是否存在该配方信息
    2. 判断连接字符串和配方名是否对应 
    3. 验证配方默认路径下文件合法性

## 2.2 配方管理前校验

### 2.2.1 新建配方

    1.验证admin.db、配方根目录都不存在待新建的配方

### 2.2.2 数据源的完整性和一致性

    1.配方一致性验证

### 2.2.3 配方迁移验证（迁移受admin.db管理的配方，如重命名）

    1.验证原配方合法性和一致性
    2.验证配方根目录下是否有新名称的文件夹存在（避免冲突）

### 2.2.4 配方迁移验证（迁移不受admin.db管理的配方，如导入）

    1.导入的配方结构是否合法(包含cache.db)
    2.验证配方根目录下是否有新名称的文件夹存在（避免冲突）

# 3.数据库读写保护

## 3.1 保存配方

```
1.写入cache.db
```

## 3.2 读取配方

    1.验证数据源完整性和一致性
    2.切换配方
    3.返回只读包装器，防止外部修改关键数据

# 4.配方管理

## 4.1 配方管理

### 4.1.1 新建配方

    1.新建SysRecipeInformationDto
    2.新建前校验
    3.admin.db插入数据

### 4.1.2 删除配方

    1.判断删除的配方是否和当前应用的配方相同（外层viewmodel判断，避免引入ICacheProvider）
    2.数据源的完整性和一致性（默认不健全的配方无法删除）
    3.+GUID重命名
    4.删除admin.db数据

### 4.1.3 导入配方

    1.拷贝配方副本，迁移验证（迁移不受admin.db管理的配方，如重命名）
    2.新增配方
    2.切换配方（外层viewmodel处理，避免引入ICacheProvider）

### 4.1.4 继承配方

    1.数据源的完整性和一致性
    2.导入配方

### 4.1.5 应用配方

    1.数据源的完整性和一致性
    2.切换数据库
    3.返回只读包装器

### 4.1.6 重命名（编辑、删除）

    1.配方迁移验证（迁移受admin.db管理的配方，如重命名）
    2.重命名文件夹
    3.更新admin.db数据

### 4.1.7 保存

    1.判断是否重命名，如果是，执行重命名方法；如果不是则更新数据
