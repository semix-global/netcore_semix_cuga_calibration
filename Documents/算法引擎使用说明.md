# 算法引擎使用说明

> 适用范围：#209 Template 分支引入的 Core.Algorithm 双引擎架构（Halcon / AlgoCSharp）
> 涉及能力：模板匹配（TemplateMatch）、清晰度（Quality）、BF 像素尺寸（PixelSize）、最佳焦面（BestFocus）、DF Y 像素尺寸（YPixelSize）

---

## 1. 概述

Core.Algorithm 项目将算法能力从 Halcon 单引擎硬编码重构为「引擎无关」架构：

- **引擎选择是运行时数据**（`AlgorithmEngineTypeEnum` 枚举），调用方代码零分支
- **参数模型与引擎一一配套**，`TryGet<T>` 做类型防呆，杜绝参数错喂
- **模板持久化走文件**：Halcon 用 `.shm/.ncc` 模型文件，AlgoCv 用 `.jpg` 预览图，无内存句柄跨会话
- **统一生命周期**：模板匹配遵循 `read → match → release` 一次性工作流（try/finally + `Model.Dispose()`）
- **Dev 环境自动 Mock**：`AlgorithmServiceProvider` 检测 Development 环境时注册 Mock 实现

## 2. 架构分层

```
调用层 ViewModels（Chuck CenterAndTheta / StageMap / Prealigner / CIB XPixelSize / Review …）
        │  AlgorithmEngineTypeEnum
        ▼
IAlgorithmEngines 外观层（AlgorithmServiceProvider · keyed DI 单例 · Dev → Mock）
        │  TemplateMatch(enum) · BestFocus(enum) · YPixelSize(enum) · PixelSize(enum)
        ▼
ITemplateMatchEngine（Generate · Read · Match）  ←── TemplateMatchSetting（尺寸·方法·阈值）
      ├──────────────────────┐
      ▼                      ▼
HalconTemplateMatchEngine   AlgoCvTemplateMatchEngine
（HAlgorithm · .shm/.ncc）   （algocv_sharp · jpg 预览图）
```

| 层 | 职责 | 关键文件 |
|---|---|---|
| 调用层 | 从 Cache / CalibrationSetting 取引擎枚举，只面向接口编程 | `CIBViewModel`、`ReviewViewModel` 等 |
| 外观层 | `IAlgorithmEngines.TemplateMatch / BestFocus / YPixelSize / PixelSize(enum)` 按枚举分发引擎；keyed DI 注册单例 | `Implements/AlgorithmEngines.cs`、`AlgorithmServiceProvider.cs` |
| 引擎抽象 | `ITemplateMatchEngine` 三方法契约 + `TemplateMatchEngineParams` 泛型参数基类；`IBestFocusEngine` / `IYPixelSizeEngine` / `IPixelSizeEngine` 单方法（Excute）契约 + sealed init-only Param/Result | `Interfaces/`、`Models/` 下各引擎配套文件 |
| 引擎实现 | 引擎无状态；模板句柄封装进 `TemplateMatchModel`（IDisposable）交调用方管理 | `Implements/Halcon/`、`Implements/AlgoCSharp/` |

**依赖方向单向向下**；引擎自身不持有匹配状态，可安全以单例注册。

## 3. 模板匹配标准调用流（read → match → release）

以 `CIBViewModel.TryGetMatchPosition` 为范本：

```csharp
// 1. 取引擎（枚举来自全局 SettingTemplateMatchParam）
var engine = algorithmEngines.TemplateMatch(
    calibrationSetting.SettingTemplateMatchParam.AlgorithmEngineTypeEnum);

// 2. 生成模板（用户框选 ROI 时）——传统一 TemplateMatchSetting
var generateParam = setting.ToGenerateParam(templateFilePath, roi, imageSize);
engine.Generate(image, generateParam, logGuid);

// 3. 读模板（每次匹配前现读，不持久化会话）
var readParam = setting.ToReadParam(engineType, templateFilePath);
var readResultRet = engine.Read(readParam, logGuid);
var model = readResultRet.Data;

try
{
    // 4. 匹配
    var matchResultRet = engine.Match(image, new MatchTemplateParam
    {
        Model = model,
        ScoreThreshold = setting.ToTemplateMatchScoreThreshold(engineType, calibrationSetting)
    }, logGuid);
    // matchResultRet.Data: Point(模板中心) / Angle(弧度) / Score / Offset(dx, -dy)
}
finally
{
    // 5. 释放——必须 try/finally 包裹
    model?.Dispose();
}
```

### 3.1 Match 返回值统一语义

| 字段 | 语义 |
|---|---|
| `Point` | 匹配到的**模板中心**（图像像素坐标，左上原点、Y 向下） |
| `Angle` | 匹配角度，弧度 |
| `Score` | 匹配得分，**越大越好**，与阈值 `ScoreThreshold` 直接比较 |
| `Offset` | `Point(dx, -dy)`：模板中心相对图像中心的偏移，**Y 已取反**（与旧 `TryTemplateMatchToOffset` 逐位一致） |

### 3.2 配置链（TemplateMatchSetting）

- `TemplateMatchSetting`：模板尺寸（128/256/512）、匹配方法、双引擎专属参数（Halcon 的 TemplateType / AlgoCv 的 Method + PyramidLevels）
- 通过 `Clone()` 深拷贝进各模块 Cache，避免引用污染
- 模板匹配引擎选择：**全局** `CalibrationSetting.SettingTemplateMatchParam.AlgorithmEngineTypeEnum`

## 4. 其余算法（走 ICalibrationAlgorithmService）

BestFocus / YPixelSize / PixelSize 已升级为引擎类（见 §5.2），仍走服务的仅剩清晰度。签名统一为「图像 → guid → 引擎枚举」，枚举取自**各模块 Cache**（模块级 UI ComboBox）：

```csharp
// 清晰度
GetQuality(image, guid, Cache.AlgorithmEngineTypeEnum);
```

> 注意：**两条引擎选择链互相独立**——模板匹配走全局 `SettingTemplateMatchParam`，Quality（服务）与 BestFocus/YPixelSize/PixelSize（引擎）走模块级 `Cache.AlgorithmEngineTypeEnum`。PixelSize 引擎枚举只活在流程 Cache，不进全局 Setting。
> 旧模板匹配接口 `TryReadTemplate / TryTemplateMatchToOffset / TryCleanTemplate / TryGenerateTemplate` 已从 `ICalibrationAlgorithmService` 删除，统一走 `IAlgorithmEngines.TemplateMatch`。`GetBestFocus / GetYPixelSize / GetPixelSize` 已从接口彻底删除，新代码统一走 `IAlgorithmEngines.BestFocus / YPixelSize / PixelSize(engine).Excute(...)`。

## 5. 扩展指南

### 5.1 两种引擎化模式

新算法接入双引擎前，先按特征选择模式：

| | A. 引擎类模式 | B. 服务内分流模式 |
|---|---|---|
| 适用特征 | 有状态/有生命周期资源（模板句柄）、多步工作流（生成→读→匹配→释放）、引擎间参数差异大，或需脱离服务签名独立演进 | 无状态单函数、一次调用出结果、引擎间参数差异小 |
| 现有范例 | 模板匹配 `ITemplateMatchEngine`（三方法）、最佳焦面 `IBestFocusEngine`、DF Y 像素尺寸 `IYPixelSizeEngine`、BF 像素尺寸 `IPixelSizeEngine`（单方法 Excute）——均 keyed DI + `IAlgorithmEngines` 外观 | `CalibrationAlgorithmServiceImpl.GetQuality` 内部 switch 分流到 `GetHAlgorithemXxx` / `GetAlgoCVSharpXxx` 私有方法 |
| 新增引擎成本 | 1 引擎类 + 1 参数类 + 1 行注册 | 1 个私有方法 + 1 个 switch 分支 |
| 调用方耦合 | 零耦合（面向接口） | 依赖 `ICalibrationAlgorithmService` 签名 |

> `GetQuality` 是 B 模式的现存范本：入参带 `AlgorithmEngineTypeEnum` → switch 分流 → 统一异常兜底（SaveErrorImage + LogAlgorithmError）。
> `GetBestFocus / GetYPixelSize / GetPixelSize` 原为 B 模式范本，已按 §5.2 升级为 A 模式引擎类。

### 5.2 将 B 模式算法升级为引擎类（BestFocus / YPixelSize / PixelSize 已完成）

BestFocus 与 YPixelSize 已按以下七步从 B 模式升级为 A 模式引擎类，后续算法迁移可作完整参照：

**第 1 步：定义引擎接口**（`Interfaces/BestFocus/IBestFocusEngine.cs`、`Interfaces/YPixelSize/IYPixelSizeEngine.cs`）

```csharp
public interface IBestFocusEngine
{
    /// <summary>评估最佳焦面（返回值统一语义：ECS 已按 start/stop 换算）</summary>
    AlgorithmResultRet<BestFocus> Excute(BitmapImage image, BestFocusEngineParam param, Guid logGuid);
}
```

契约要点：方法名统一 `Excute`（项目约定拼写）；返回值包 `AlgorithmResultRet<T>`；图像统一走 `BitmapImage` 枢纽。

**第 2 步：定义参数/结果模型**（`Models/BestFocus/`、`Models/YPixelSize/`）

- sealed class + init-only 属性（无 UI 绑定需求，不用 ObservableObject）+ `ToHtmlAnonymous()` 供 HtmlLog 输出
- `BestFocusEngineParam { StartEcs, StopEcs, BestFocusType }`；`YPixelSizeEngineParam { StandardMaskSquareYSize }`
- `YPixelSizeResult { YPixelSize, DrawingImage, YProjects, ResultIndexes }`；BestFocus 复用既有 `BestFocus` 模型

**第 3 步：实现两个引擎**（`Implements/Halcon/` 与 `Implements/AlgoCSharp/`）

- `HalconBestFocusEngine` / `HalconYPixelSizeEngine`：原 `GetHAlgorithemXxx` 私有方法整段迁入
- `AlgoCvBestFocusEngine` / `AlgoCvYPixelSizeEngine`：原 `GetAlgoCVSharpXxx` 迁入；竖图/正向图方向契约逐字保留（raw 链路 `ToAlgoCVImage` 时 `isRawSource: true` 才转置）
- ECS 换算（`StartEcs + bestX / image.Size.Width * (StopEcs - StartEcs)`）随迁移进入 BestFocus 引擎内部
- 错误处理与 `HalconTemplateMatchEngine` 一致：catch → SaveErrorImage + LogAlgorithmError → throw

迁移原则：**复用现有实现逻辑，保持行为不变**（坐标语义、异常路径原样搬移）。

**第 4 步：外观层加分发方法**（`IAlgorithmEngines` + `AlgorithmEngines`）

```csharp
IBestFocusEngine BestFocus(AlgorithmEngineTypeEnum engine);
IYPixelSizeEngine YPixelSize(AlgorithmEngineTypeEnum engine);
// 实现：=> serviceProvider.GetRequiredKeyedService<...>(engine)
```

**第 5 步：keyed DI 注册**（`AlgorithmServiceProvider`：Dev 注册 Mock，Production/Staging 注册真实引擎）

```csharp
services.AddKeyedSingleton<IBestFocusEngine, HalconBestFocusEngine>(AlgorithmEngineTypeEnum.HAlgorithm);
services.AddKeyedSingleton<IBestFocusEngine, AlgoCvBestFocusEngine>(AlgorithmEngineTypeEnum.AlgoCSharp);
```

**第 6 步：调用方迁移 + 删除旧接口**

- `CalibrationViewModelBase` 暴露 `AlgorithmEngines` 属性（`HostApplication.GetRequiredService<IAlgorithmEngines>()`），各 VM 零构造改动
- 调用点统一写法：

```csharp
var ret = AlgorithmEngines.BestFocus(Cache.AlgorithmEngineTypeEnum).Excute(image,
    new BestFocusEngineParam { StartEcs = startEcs, StopEcs = stopEcs, BestFocusType = Cache.AlgorithmBestFocusTypeEnum }, HtmlLogUniqueId);
var bestFocus = ret.Data ?? throw new CugaException(ret.ErrorMsg);
```

- 旧 `GetBestFocus / GetYPixelSize / GetPixelSize`（接口 + Impl + MockImpl 三处）已删除，统一走 `IAlgorithmEngines.BestFocus / YPixelSize / PixelSize(engine).Excute(image, param, guid)`

**第 7 步：同步 Mock 与测试**

- Dev 环境 Mock（`AlgorithmServiceProvider` 的 `IsDevelopment` 分支）：BestFocus 保留「固定 raw 资产替换输入图」现状（`Assets\Data\..._PMT08-CH2_8.raw` 读入后委托真实引擎）；YPixelSize 随机结构（1064 投影点 + 10 索引）
- 单元测试（见 §7）：`BestFocusEngineTest`（双引擎 × 双 raw 资产）、`YPixelSizeEngineTest`（真实 + Mock 结构断言）

### 5.3 为模板匹配接入第三个引擎

1. **定义参数模型**：继承 `TemplateMatchEngineParams`，放引擎专属参数
2. **定义引擎类**：实现 `ITemplateMatchEngine`，遵守三方法契约
   - `Generate`：裁剪 ROI → 建模板 → 落盘文件
   - `Read`：从文件恢复模板 → 返回 `IDisposable` 模型包装
   - `Match`：遵守 §3.1 统一语义（Score 越大越好 / 模板中心 / Offset Y 取反）
3. **注册 DI**：`AlgorithmServiceProvider` 加一行 keyed 注册；`AlgorithmEngineTypeEnum` 加枚举值
4. **配置 UI 自动生效**：`TemplateMatchSettingUserControl` 的 ComboBox 经 `EnumBindingSource` 绑定，新枚举值自动出现
5. **阈值适配**：在 `EnumAlgorithmExtension.ToTemplateMatchScoreThreshold` 补新引擎分支

扩展成本：1 个引擎类 + 1 个参数类 + 1 行注册 + 1 个枚举值；调用层与 ViewModel 零改动。

> 建议：在 `ITemplateMatchEngine.Match` 契约层统一「得分越大越好」语义（当前 Sqdiff 系方法存在语义反转隐患，见 §7），新引擎自然继承正确行为。

## 6. 界面切换算法库

### 6.1 两类切换入口

| 入口 | 影响范围 | 绑定源 |
|---|---|---|
| **模块 Step 界面** 的 "Algorithm Engine Type: " ComboBox | 仅当前模块 | `Cache.AlgorithmEngineTypeEnum`（模块级，Clone 进缓存） |
| **Setting 窗口**（File → Setting）的引擎 ComboBox | 全部模板匹配模块 | `CalibrationSetting.SettingTemplateMatchParam.AlgorithmEngineTypeEnum`（全局） |

已接入模块级切换的界面：Microscope PixelSize/Focus Step2View、CIB YPixelSize Step4View、SC Step4View、Relay Step6View、AOD BestFocusAndAstigmatism Step5View、OpticsBestFocusWindow、ChirpAODWaveformTrainingWindow 等。

其中 BestFocus / YPixelSize / PixelSize 相关界面（CIB YPixelSize Step1View、Microscope PixelSize Step2View、SC Step4View、Relay Step6View、AOD Step5View、OpticsBestFocusWindow、ChirpAODWaveformTrainingWindow）已直连 `IAlgorithmEngines` 引擎调用；Quality 界面仍走 `ICalibrationAlgorithmService`。PixelSize 的引擎 ComboBox 与 Param 控件同挂 Step2View，枚举由 `MicroscopePixelSizeCache.AlgorithmEngineTypeEnum` 自管。

### 6.2 标准 XAML 模板（摘自 Microscope Focus Step2View）

```xml
<hc:ComboBox hc:TitleElement.Title="Algorithm Engine Type: "
             hc:TitleElement.TitlePlacement="Left"
             hc:TitleElement.TitleWidth="180"
             ItemsSource="{Binding Source={extensions:EnumBindingSource EnumType={x:Type algorithm:AlgorithmEngineTypeEnum}}}"
             SelectedItem="{Binding Cache.AlgorithmEngineTypeEnum}">
    <hc:ComboBox.ItemTemplate>
        <DataTemplate>
            <TextBlock Text="{Binding Converter={StaticResource EnumDescriptionConverter}}" />
        </DataTemplate>
    </hc:ComboBox.ItemTemplate>
</hc:ComboBox>
```

要点（`EnumBindingSource` / `EnumDescriptionConverter` 均来自 Net.Utilities WPF 组件，`hc:` 为 HandyControl）：

- `EnumBindingSource`：MarkupExtension，把枚举所有值展开为 ItemsSource——**新引擎枚举值加进 `AlgorithmEngineTypeEnum` 后下拉自动出现，无需改 XAML**
- `EnumDescriptionConverter`：显示枚举的 `[Description]` 中文描述，需在枚举值上补特性：

```csharp
public enum AlgorithmEngineTypeEnum
{
    [Description("Halcon 引擎")]
    HAlgorithm,

    [Description("AlgoCSharp 引擎")]
    AlgoCSharp,
}
```

### 6.3 引擎联动参数面板（模板匹配专属）

`TemplateMatchSettingUserControl` 通过 `Engine` 依赖属性感知当前引擎，DataTrigger 按 Engine 值显隐引擎专属参数区（HAlgorithm 显示 TemplateType，AlgoCSharp 显示 Method / PyramidLevels）：

```xml
<controls:TemplateMatchSettingUserControl
    DataContext="{Binding Cache.TemplateMatchSetting}"
    Engine="{Binding DataContext.CalibrationSetting.SettingTemplateMatchParam.AlgorithmEngineTypeEnum,
             RelativeSource={RelativeSource AncestorType={x:Type UserControl}}}" />
```

### 6.4 切换操作流程（用户视角）

1. 进入对应模块 Step 界面（或 Setting 窗口切换全局模板匹配引擎）
2. 在 "Algorithm Engine Type: " 下拉中选择目标引擎
3. 按需调整引擎专属参数（模板匹配参数面板会随引擎联动显隐）
4. **执行校准流程并 Save**——Save 是最后一步，切换结果随缓存/设置持久化
5. 注意：模板匹配引擎切换后，旧引擎生成的模板文件（.shm/.ncc）不会被新引擎读取（AlgoCv 读 .jpg 预览图），**建议切换引擎后重新生成模板**
