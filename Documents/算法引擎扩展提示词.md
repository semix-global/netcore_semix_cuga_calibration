# 算法引擎扩展提示词（开放引擎参数设置，含界面）

> 沉淀自 2026-10-24 双引擎参数设置开放实战（样板 = TemplateMatchSetting 系，复刻 = YPixelSizeSetting / PixelSizeSetting 系；离散字符串再收敛为 AlgorithmPeriodOpEnum）。
> 用途：新引擎接入 / 给既有引擎开放参数设置时，将本提示词整体投喂给 AI 或照做。
> 铁律：旧链路（ICalibrationAlgorithmService、VM 旧轨）保持不动，只做 IAlgorithmEngines 新轨；默认不主动编译，仅用户明确要求时执行。

## 一、前置盘点（动手前必须确认）

1. **引擎清单**：`IAlgorithmEngines`（Core.Algorithm\Interfaces\IAlgorithmEngines.cs）现有成员 = BestFocus / YPixelSize / PixelSize / TemplateMatch，keyed DI 按 `AlgorithmEngineTypeEnum`（HAlgorithm / AlgoCSharp）分发。引擎统一方法名 `Excute`（非 Execute）。
2. **EngineParams 子类**：目标引擎须已有 `Xxx : EngineParams` 参数类（如 AlgoCvTemplateMatchParams / AlgoCvYPixelSizeParams / AlgoCvPixelSizeParams）。**无参数类 = 无可开放项**（BestFocus 两引擎均无参数类，待引擎侧有参数类时再开放）。若需先补参数类：init-only 属性 + 默认值 + `ToHtmlAnonymous` + 底库结构体转换方法。
3. **raw 底座裁定**：Halcon 引擎 → `RAWImageFactoryV2`（外部包 net.utilities.algorithms.halcon）；AlgoCSharp 引擎 → `RAWImageFactoryV3`（仓库 Net.Utilities.Algorithms.AlgoCSharp）。V2/V3 `CreateImage(string,bool)` 产物理正向图（世界口径）。
4. **入参形态三分规则**：① BestFocus/YPixelSize = `DarkFieldImageDTO` 双通道（GetImage() + RawImageFilePath）；② 模板匹配 Generate/Match = `BitmapImage` 显示域；③ GetQuality / PixelSize = `BitmapImage`。
5. **业务流程定位**：找出调用该引擎的 VM（`AlgorithmEngines.Xxx(engine).Excute(...)` 调用点）、其 Cache 类、其 View 目录。

## 二、六步落地（以 Xxx 引擎为例）

### ① Setting 聚合类（Core.Models\Models\Setting\XxxSetting.cs）

- 公共参数平铺 + 各库子对象（`Halcon:` / `AlgoCSharp:`）+ 每级 `Clone()`，字段与引擎 Params 类一一对应、**默认值同步**。
- 引擎选择不冗余存储：由流程 `Cache.AlgorithmEngineTypeEnum` 或全局 `CalibrationSetting` 决定。
- 某库无参数类时子对象留空，注释标明"待引擎扩展时增设"。
- **离散字段从 Setting 起就是枚举**：封闭字符串 / 码表数值不得以 `string` 或裸 `int` 落 Setting（见下方传参规范）。

```csharp
public sealed class XxxSetting
{
    // 引擎选择不冗余存储：转换时由调用点显式传 engine 参数（见 ⑥）
    public AlgoCSharpXxxSetting AlgoCSharp { get; set; } = new();
    public XxxSetting Clone() => new() { AlgoCSharp = AlgoCSharp.Clone() };
}

public sealed class AlgoCSharpXxxSetting
{
    // ... 字段
}
```

### 传参规范（Setting → Params → 底库）

开放参数前先分类，再决定类型与控件：

| 参数形态 | Setting / Params 类型 | UI | 底库边界 |
|---|---|---|---|
| 封闭字符串（如 period_op `"mean"`/`"std"`/`"range"`） | `Core.Models.Enums.Algorithm` 下新建 `AlgorithmXxxEnum`（带 `[Description]`） | `ComboBoxExtend` + `EnumBindingSource` + `EnumDescriptionConverter` | 仅 `ToXxxConfig()` 调 `EnumAlgorithmExtension.ToAlgoCvXxx()` 转底库字符串 |
| 看起来是数值、实际是码表（如 TemplateMatch Method 0–5） | 同上，枚举成员可显式赋底库整数值 | 同上 ComboBox | 需要时在 Config 边界映射到底库 enum/int |
| 连续量 / 开区间整数 / `0=Auto` 哨兵 | `double` / `int` 保持原样 | `NumericUpDown` + `NumericUpDownExtend` | 原样拷贝；哨兵在 Config 内解析（如 PeriodHalf 0 → 按掩膜规格扫描窗） |
| 真正自由文本（路径、备注） | `string` | 外置标题行 + `TextBoxExtend` | 原样拷贝 |

链路：`Setting 枚举（可变）` → `AlgoCvXxxParams 枚举（init-only，全字段拷贝，类型已对齐）` → `ToXxxConfig()` 才出现底库 `string`/`int`。

```csharp
// Core.Models\Enums\Algorithm\AlgorithmPeriodOpEnum.cs
public enum AlgorithmPeriodOpEnum
{
    [Description("Mean")] Mean,
    [Description("Std")] Std,
    [Description("Range")] Range
}

// Core.Models\Extensions\EnumAlgorithmExtension.cs
public static string ToAlgoCvPeriodOp(this AlgorithmPeriodOpEnum periodOp) => periodOp switch
{
    AlgorithmPeriodOpEnum.Std => "std",
    AlgorithmPeriodOpEnum.Range => "range",
    _ => "mean"
};

// Config 边界（Core.Algorithm 侧 ToBfPixelSizeConfig / ToDfPixelSizeConfig）
period_op = PeriodOp.ToAlgoCvPeriodOp();
```

禁止：Setting/Params/UI 任何一层再暴露底库字符串（禁止 `public string PeriodOp { get; set; } = "mean"`）。Cookie 按仓库惯例序列化为整数，不做额外 string converter。

### ② 封装控件（同目录 XxxSettingUserControl.xaml / .xaml.cs）

四条 UI 铁律（均 2026-10-24 用户裁定）：

1. **默认折叠**：外壳 `Expander IsExpanded="False"`（低频修改项，减少界面占用）。
2. **库专属区按 Engine 区级显隐**（DataTrigger 收敛到容器，勿逐控件套）；不要把控件放 ViewModel。
3. **离散参数必须枚举包装后再开放**：封闭字符串 / 码表数值禁止 TextBox 自由输入；用 `ComboBoxExtend` + `EnumBindingSource` + `EnumDescriptionConverter`（样板 = TemplateMatch Method / PixelSize PeriodOp）。

### ⑤ 引擎参数转换扩展 + VM 调用点（Core.Algorithm 侧）

Setting（可变）→ Params（init-only）全字段拷贝（枚举类型已对齐，此处不再 ToString）；底库字符串/int 只出现在 `ToXxxConfig()`。保留无 setting 的旧重载（默认参数，测试可用）。

```csharp
// extension(AlgorithmEngineTypeEnum engine) 块内：带业务层设置的重载
public XxxEngineParam ToXxxEngineParam(..., XxxSetting setting) => new()
{
    ...,
    EngineParams = engine == AlgorithmEngineTypeEnum.AlgoCSharp ? setting.AlgoCSharp.ToAlgoCvXxxParams() : null
};

// 独立静态扩展类（勿放 extension 块内！块内只能声明该 receiver 的成员）
public static class AlgoCSharpXxxSettingExtensions
{
    internal static AlgoCvXxxParams ToAlgoCvXxxParams(this AlgoCSharpXxxSetting setting) => new() { /* 全字段拷贝 */ };
}
```

VM 调用点改为：`Cache.XxxSetting.ToXxxEngineParam(引擎真值, ...)`（engine 作首参显式传入，见下方防呆小节）。

### ⑥ 引擎一致性防呆（2026-10-27 改版裁定，必做）

防"接口入参 engine 与接口实现显式调用的库参数不一致"。失败模式 = 硬失败，不静默降级。

**单一防线（显式 engine 参数 + 引擎入口类型兜底）**：

- **转换方法显式收 engine 参数**：`ToXxxEngineParam(AlgorithmEngineTypeEnum engine, ...)` / `ToReadParam(engine, ...)` 等，engine 永远是首参。编译器强制每个调用点提供引擎真值（流程 `Cache.AlgorithmEngineTypeEnum` 或全局 `CalibrationSetting.SettingTemplateMatchParam.AlgorithmEngineTypeEnum`），不可漏写、无残留状态。
- **引擎入口天然兜底（勿弱化）**：`EngineParams.TryGet<T>` 类型不匹配 → false + 明确错误信息（null 表示用默认参数，合法放行）；Match 侧 `param.Model is not XxxTemplateMatchModel` 同理校验。错库参数在此硬失败（`EngineParams must be {T}`）。
- **历史（2026-10-26 ForEngine/EnsureEngine/EnsureSubEngine 三层防呆已于 2026-10-27 移除）**：ForEngine 把方法参数变成可漏写、可残留、随 Clone/JSON 持久化携带的暂态字段；EnsureEngine 全仓库零调用（死代码）；EnsureSubEngine 防的错位场景由 TryGet 兜底。引擎真值在调用点总是显式可得（流程 Cache 或全局 CalibrationSetting），不存在"构造时固化"的需求。

**模板匹配范例**（TemplateMatchSettingExtensions.cs）：

```csharp
public EngineParams ToEngineParams(AlgorithmEngineTypeEnum engine) =>
    // 每个引擎分支只读本库的子对象；错库参数由引擎入口 EngineParams.TryGet 硬失败兜底。
    engine == AlgorithmEngineTypeEnum.HAlgorithm
        ? new HalconTemplateMatchParams { TemplateType = setting.Halcon.TemplateType }
        : new AlgoCvTemplateMatchParams { Method = setting.AlgoCSharp.Method, ... };
```

**调用点形态**（engine 显式作首参）：

```csharp
Cache.TemplateMatchSetting.ToReadParam(CalibrationSetting.SettingTemplateMatchParam.AlgorithmEngineTypeEnum, Cache.Item.TemplateFilePath)
```

**新引擎接入成本（三步）**：① Setting 聚合 + 库子对象（无接口标记）；② ToXxxEngineParam 及所有转换扩展收显式 engine 首参，分支内只读本库子对象；③ 每个调用点把引擎真值作首参传入。

**Alignment 链路例外（2026-10-28 写死裁定）**：alignment 的模板匹配执行在远端底层（C2M 协议之后），本地引擎切换对它无意义——引擎维度写死 Halcon，不接入上述引擎切换体系：

- `MarkAlignSite1(AlgorithmTemplateSizeEnum)` 只收模板尺寸（公共属性）；匹配类型由协议收口点（WCF/GRPC 实现）固定编码 Ncc（抓模板阶段）。底层替换为 algo 时仅需修改协议层收口点 + 扩签名。
- **site 层纯底层真值**：`AlignmentSiteDto.TemplateMatchSetting` 跟随接口返回（AdaptIn 反解），生产端不显式赋值（不 Clone、不设阈值——Mark2/Alignment/AlignmentVerify/AlignmentDarkField 服务层入口统一按 site 的 TemplateType 从 common setting 取阈值）。
- **引导在 Mark2 底层**：site2 的精确定位由 `MarkAlignSite2(site1)` 远端匹配实现（当前视野匹配定位），生产端无需本地预匹配。Prealigner（ChuckPrealigner）与 AlignmentWindow 形式统一：台面预置大概位置（DiePitch 理论推算 / 人工走位）→ Mark2 直接定位 → site=返回值。
- **cache 层 setting 已清除（零消费者裁定）**：`AlignmentCacheBase.TemplateMatchSetting`（ParamWindow 的 TemplateType 编辑 + 窗口 Status 显示随之删除）、`ChuckPrealignerCache` 的 `Low/HighTemplateMatchSetting` 与 `Low/HighSiteTemplateFilePath`（本地模板生成 + 快取匹配整链删除——产出无下游）均不存在；Prealigner 的 Mark1 参数为独立的 `Low/HighTemplateSizeEnum` 字段（对齐 AlignmentCacheBase 的 Low/HighSizeEnum 形态）。

## 三、坑清单（实战验证）

| 坑 | 正解 |
|---|---|
| 封闭字符串 / 码表数值用 TextBox 或裸 int 开放 | 先 `AlgorithmXxxEnum` + `[Description]`，Setting/Params 同类型，UI 走 ComboBoxExtend |
| Setting/Params 存 `"mean"` 再在 UI 绑 string | 从 Setting 起就是枚举；只在 `ToXxxConfig()` 调 `ToAlgoCvXxx()` |
| TextBox + TitleElement.Title 不显示 | TextBoxExtend 模板不渲染；封闭集改 ComboBox；自由文本才外置 TextBlock 标题行 |
| NumericUpDown / ComboBox 缺 Extend Style | Title 空白；必须 `NumericUpDownExtend` / `ComboBoxExtend` |
| C# extension block 内写其他 receiver 的 `this` 扩展方法 | 编译错误；独立 static class |
| Cache Clone 漏新增 Setting | 克隆静默丢设置；属性加入时同步 Clone |
| 库专属区逐控件套 DataTrigger | 冗长；收敛到容器区级 |
| 控件内做引擎选择逻辑 | 不放 ViewModel；控件只收 Engine DP |
| Setting 聚合存 EngineType 暂态字段（ForEngine 模式） | 引擎真值由调用点显式传 engine 首参；Setting 不存引擎状态（2026-10-27 移除 ForEngine 机制） |
| 引擎分支写反（如 HAlgorithm 分支读 AlgoCSharp） | 分支内只读本库子对象；错库参数由引擎入口 EngineParams.TryGet 硬失败兜底 |
| 主动跑编译/测试 | 默认禁止（用户全局偏好）；仅明确要求时执行 |

## 四、验收要点（用户要求时才执行）

1. `dotnet build ... -f net48` 0 错误（net48 为准，忽略 net10）。
2. 相关单测：测试直接构造 `new XxxEngineParam{...}` 用默认参数重载（不依赖业务 Setting）；raw 资产值锁定用例不受影响。
3. 界面人工验收：Expander 默认折叠、引擎切换同页、库区随 Engine 显隐、离散参数下拉可选（无自由输入）、全部标题可见（Extend Style 齐全）。
